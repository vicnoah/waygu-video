# Delivery roadmap

The Scenra files in `design/` define the product. The current app connects to Emby, Jellyfin, Plex and Flymoo, imports selected video libraries, lists and searches titles, shows movie and series details, and plays and reports progress. Jellyfin supports Quick Connect. Plex supports account authorization by browser or QR code and lets users choose a discovered server. The app has a native video path, an optional desktop libmpv path, synchronized local and DandanPlay comments, and a dismissible next-episode countdown. Emby, Jellyfin and Plex support a configurable streaming bitrate limit.

## Media sources

- Emby and Jellyfin support LAN discovery by UDP. Flymoo browses the advertised media service over mDNS and prefills the server’s name and port. It also supports standard fnOS LAN ports, the media gateway path, same-host gateway redirects, and finding a gateway from an FN ID. Saved FN IDs let catalog requests and interrupted playback try updated routes after the configured addresses fail. The old access-code session stays on its original HTTPS origin. A new protected origin requires entering the code in the FN Connect dialog. Mobile discovery, live FN Connect and vendor client P2P remain open. [Discovery review](ui-review/add-source.md#flymoo-discovered-source) · [FN Connect review](ui-review/source-login.md#fn-connect-route-and-access-code) · [Recovery review](ui-review/phone-source-settings.md#fn-connect-route-recovery)
- The import form shows each authenticated library’s title count. Its library badges open category and home visibility options. Saved libraries support visibility and per-source ordering. The phone source settings refresh the server’s library list. Refreshes keep visibility, categories and ordering for known libraries and hide new libraries until they are enabled.
- All Sources combines movies and series with matching IMDb or TMDB IDs. Source order supplies the default copy. The media source settings let users reorder sources and turn matching off. A configured backup address must report the saved server ID before the app uses the account. New requests prefer the local address and can fall back to the verified backup. A failed player can reopen the selected version on the other address at its last position. The desktop settings expose a separate remote bitrate limit. Native clients can approve an HTTPS certificate fingerprint and store custom request headers for a specific server origin. The connection form reports measured latency and can retest without discarding import selections. Verify network changes on devices and account recovery. [Connection review](ui-review/source-login.md)
- Verify Plex account authorization with a real account and a claimed server, including remote and relay connections. Flymoo signs artwork, media ranges, and HLS requests at the point of use. Verify the remaining version-specific payloads and test on a physical NAS. [Flymoo playback comparison](ui-review/phone-player.md#flymoo-online-and-offline-playback)

## Playback and library

- Movie and series details offer the matched copies in visible imported libraries. Each copy offers the versions or qualities its server exposes. Playback reports progress to the selected server. The player switches versions at the current position on that server. Emby, Jellyfin and Plex support playback presets that cap both server output height and bitrate. The phone quality panel shows both limits. Playback settings can prefer the highest quality, fit the configured streaming bitrate or remember the last version played. Add choosing other servers inside the player. [Quality panel comparison](ui-review/phone-player.md#subtitles-and-audio)
- The desktop movie library offers grid, list and poster wall layouts, a pinyin index, stackable filters and saved smart collections. The GTK comparison records the remaining sidebar and platform differences.
- Desktop movie details keep the sidebar visible and show playback actions, version and track selection, cast, related titles, file metadata and DandanPlay matching.
- Continue Watching shows one record per matched movie or episode, ordered by the server's last-played time. Records without a timestamp retain their source order. The selected card resumes its own server's copy and position. The app caches the last successful resume list for each account, applying the current library visibility when a server is unavailable.
- Playback checkpoints that fail to reach the server survive app restarts and appear in Continue Watching. The app retries after leaving the player or restarting and checks the server's current progress before sending a checkpoint. Turning off Remember playback progress prevents new checkpoints and player reports for subsequent sessions. Existing resume points can still be used. Flymoo compares positions when the server supplies no timestamp. [Progress settings comparison](ui-review/phone-player-settings.md#remember-playback-progress)
- The player switches Emby, Jellyfin and Plex audio at the current position, supports local SRT and WebVTT files, text subtitles from Emby and Jellyfin, external SRT and WebVTT from Plex, subtitle delay and playback speed on capable backends.
- The landscape phone player has touch gestures for play and pause, seeking, temporary 2× speed, picture dimming and playback volume. Playback settings save independent preferences for brightness, volume and seek swipes. The timeline displays chapter marks and server seek previews. The player offers six picture modes, chapter jumps, A/B repeat and a sleep timer that follows autoplay. Danmaku starts below the header and system insets across the picture modes. Add native decoder ranges to the phone timeline when the playback API exposes them. Frame export and audio/video sync remain open. Verify orientation, gestures and Picture in Picture on physical phones. [Player comparison](ui-review/phone-player.md)
- The DLNA sender discovers LAN renderers or accepts an IP or description URL, protects media server credentials with a receiver-specific proxy, and resumes locally at the receiver's progress. Emby, Jellyfin and Plex can provide an HLS stream to renderers that advertise it. Add AirPlay and Chromecast, remote track changes, and target-device verification. [Casting comparison](ui-review/casting.md)
- Phone settings save separate Wi-Fi and cellular playback profiles, a cellular confirmation, default speed, seek intervals, picture mode, ordered subtitle languages and a preferred audio language. The player reads the transport when opening a stream. Phone and desktop share a preference for direct play or server transcoding on Emby, Jellyfin and Plex. Text captions use the chosen scale, color, background and position. Automatic Picture in Picture is wired to the iOS video backend and needs device verification. [Phone settings comparison](ui-review/phone-player-settings.md#playback)
- The Android package can continue playback audio with the app in the background. Its media service keeps the original player active and exposes pause through the system media controls. Verify screen-off playback on physical phones and tablets. Standalone background audio on iOS and HarmonyOS remains open. [Background audio comparison](ui-review/phone-player-settings.md#background-audio)
- The desktop Settings window uses a searchable sidebar and includes General, Playback, Danmaku and Media Sources. It saves startup, language, engine, bitrate, seek and countdown preferences, shows the media server connection status and manages library visibility. The [GTK comparisons](ui-review/desktop-settings.md) track unavailable settings and remaining platform verification.
- The desktop player has a seek preview and a comment heatmap, player shortcuts, an episode list, danmaku controls, and live libmpv information. Its timeline marks the intervals libmpv can seek in the demuxer cache and leaves the gaps visible. It saves comments locally for each title. [Desktop timeline comparison](ui-review/desktop-player.md#episodes-and-timeline)
- Desktop direct play with libmpv switches embedded audio and subtitles in place, including Flymoo streams and embedded Plex subtitles. It supports subtitle delay alongside the independent danmaku overlay.
- Verify codec-driven direct stream and transcode decisions and playback when networks change midstream. Add Flymoo track selection and embedded Plex subtitles on native backends, subtitle image formats, online subtitle search, custom fonts, bilingual rendering, per-platform decoder and audio controls, and caption preferences for embedded libmpv tracks. Verify next-episode playback across seasons on TV devices.
- The player can skip intro and credit ranges supplied by Emby, Jellyfin and Plex. Explicit markers take precedence over named chapters for the selected version. Split credits preserve intervening scenes. The phone and desktop settings share the preference. When a marker is missing, the player can compare audio with two other episodes in the same season. Emby and Jellyfin supply PCM audio. The desktop fallback for Plex and Flymoo uses an installed FFmpeg and the original file. Verify Flymoo inference, add portable audio decoding for providers without PCM streams, and verify skips on target devices and during casting. [Playback evidence](ui-review/phone-player.md#intro-and-credit-skips)
- With DandanPlay developer credentials, the player matches original files by fingerprint, offers episode search, remembers bindings per media source, and reuses their numbering within a season. It caches downloaded comments for 24 hours on native platforms and combines them with local XML, JSON or ASS comments. Display and filter preferences are shared by the native and libmpv renderers. Playback applies keyword, regular expression, sender and comment type filters, marks repeat counts, and saves time offsets per item. The phone settings preview uses the playback scheduler and shows local cache usage. Add adjacent-file discovery, individual online sources and public comment sending. Verify the ASS document picker on target devices. ## Platform verification

Run checks locally during development. Start the GitHub Actions build and test matrix manually when a milestone is ready for platform verification. Select the Apple scope when the milestone needs Xcode builds and Apple simulators.

- Test signed macOS packages and iOS and tvOS builds on a Mac with Xcode. Verify controller, keyboard and focus behavior on TV devices.
- Complete Android TV remote-control and store-banner verification, and verify signed release builds on TVs, phones and tablets.
- Verify HarmonyOS signing, authenticated LAN sessions and video playback on HarmonyOS phones and tablets, including secure credential persistence and authenticated streams.
- Verify Linux and Windows runtime behavior across both architectures, including media codecs, hardware decoding and libmpv distribution.
